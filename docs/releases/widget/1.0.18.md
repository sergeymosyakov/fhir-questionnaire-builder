This release is mostly about the renderer being right: what it calculates, what it saves into the QuestionnaireResponse, and how it treats questionnaires you did not write. The most important fix comes first: Show When rules now react to the answers given in the widget.

## Show When and conditions
- Standard `enableWhen` rules react to the answers given in the widget. In 1.0.17 they were checked against a page-wide answer store that a widget never fills, so a question that depends on another answer stayed unavailable ("waiting") after the controlling question was answered. Rules written as `enableWhenExpression` were not affected. (#349)
- A Show When rule that compares numbers for equality compares numbers, and an unanswered number or quantity no longer satisfies `<`, `<=`, `>` or `>=`. (#242, #342)
- Several preselected options (initial answers) survive the import. (#242)

## Calculations
- A calculated value inside a repeating group (or a repeating table) is now computed from its own entry. Before, entries could show empty values or values based on another entry. A total outside the group still sees every entry. (#320)
- A calculated date or dateTime shows its result without "Read-only" being set, and a repeating question with a calculated value no longer stays empty. (#317)
- Calculations that read a `%variable` are recalculated in dependency order. (#342)

## What the response contains
- Open-choice: a value picked from the list is saved as a coded answer (`valueCoding`); text typed into the field is saved as a string (`valueString`), even when it equals an option. (#227)
- Choice answers backed by a value set keep their code system and display in the response, taken from the question's options, an expanded value set, or a response you loaded. (#228)
- The response no longer contains invalid numbers, empty units or an empty questionnaire reference. (#244)
- A quantity filled in part (a value without a unit, or the reverse) now fails the item's check, the status badge and its group's pass/fail mark, and the half-filled state survives a re-render. It was never part of the response, and still is not. (#346, #356)

## Extensions and value sets
- Extensions are read at the addresses and value types the specification defines (the older addresses are still read). (#240)
- R5-style `coding` questions, including open-choice with `answerConstraint: optionsOrString`, are read as choice or open-choice. Value sets: `$expand` uses the `count` parameter, and contained value sets are read from their expansion, listed concepts, nested sets and exclusions. (#243)
- Value sets shared by several questions are requested once, with at most four requests at a time. (#353)

## Language
- Answer option labels follow the active language (dropdown, radio, check-box, open-choice, table) when translations exist. Codes, stored answers and calculations do not change. Labels from a live value set lookup are not translated. (#322)

## Questionnaires you did not write
- Media in an imported questionnaire is shown only when its address is http(s), relative or an image/audio/video `data:` URL, and without sending a referrer. (#257)
- A questionnaire nested more than 100 levels deep is refused instead of overflowing the stack. (#257)
- Keys such as `__proto__` or `constructor` in imported maps, translations and patches are ignored. (#256)
- A malformed item list (for example `item` that is not a list of objects) is refused before anything is replaced. (#344)

## Checks and validation
- A group's pass/fail mark counts every rule an item enforces: pattern, minimum length, decimal places, file size and reference type, not only required fields. (#252)
- The decimal-places check catches exponent notation (`1e-7`), and a failing FHIRPath constraint is now also logged to the console. (#255)

## Smaller fixes
- The unit dropdown of a quantity and the resource-type dropdown of a reference no longer reopen right after you pick an entry with Enter. (#279)
- A slider without a defined step uses step 1, and a Yes/No question gets its accessible name from the question text. (#342)
- An error while building or rendering the preview no longer leaves the form stuck behind the progress overlay; it is reported through the widget's `error` event. (#342)

## API
- New: the `error` event is also emitted when the questionnaire passed to the widget cannot be loaded (invalid JSON, not a Questionnaire, nested too deeply, malformed item list). It fires after the constructor returns, so `widget.on('error', …)` registered right after `new QuestionnaireRenderer(…)` receives it. The widget stays empty in that case, and the loader still shows its own error dialog on the page, as before. (#356)
- Nothing is removed or renamed.

## Check before upgrading
- Questions that depend on another answer through `enableWhen` now become available when that answer is given (see above). A form that worked around the old behaviour may behave differently.
- If your code reads what a respondent typed into an open-choice from `valueCoding`, read `valueString` instead.
- In `getResponse()`: `questionnaire` is omitted when the Questionnaire has neither `url` nor `id` (it was an empty string); `valueInteger` and `valueDecimal` are left out for values that are not numbers (they could be saved as 0); an empty unit is left out; choice answers now carry `system` and `display` where they can be resolved.
- A Show When rule comparing numbers for equality now compares numbers, so a rule that relied on comparing text may behave differently.
- With `config.terminology.corsProxy` set, value-set expansion requests to the known CORS-enabled hosts (`hapi.fhir.org`, `r4.smarthealthit.org`, `launch.smarthealthit.org`, `test.ahdis.ch`) now go directly instead of through the proxy. `terminology.hl7.org` is no longer on that list, so populate and lookup requests to it now go through the proxy.
- An item without `text` is shown without a label of its own; its linkId badge is still shown (before, the linkId was repeated as the label).
- Large repeating groups with calculations do more work on each recalculation (one copy of the response per entry per calculation).

## Size
- The JavaScript bundle is about the same size as 1.0.17 (3.92 MB → 3.94 MB, +0.4%); the CSS is essentially unchanged.

## Not covered
- Option labels from a live value set lookup, and table cells other than the display column, are not translated.
