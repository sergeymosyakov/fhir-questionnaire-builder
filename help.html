SDC Server
sdc-questionnaire-definitionExtractMarks a group item as an extraction context. All child items with item.definition will be extracted into a FHIR resource of the type specified in the definition URL (e.g. StructureDefinition/Patient#Patient.name.family). The element type and cardinality are taken from the R4 model (a coded answer becomes a CodeableConcept / Coding / code as needed, repeating elements are lists, single-valued ones are not); a group with a definition is one element per response instance; answers nested under answers are extracted; repeating extract groups produce one resource per instance. The extension parameters definition (profile), fullUrl, ifNoneMatch, ifMatch, ifNoneExist and ifModifiedSince are used for the Bundle entry; no resource id is invented.Builder: add extension via import; Save ▾ → Definition Extract to run extractionImport a questionnaire with definitionExtract groups, fill answers, then Save ▾ → Definition Extract · FHIR JSON Bundle → Download.
sdc-questionnaire-definitionExtractContextAlternative marker for a group that is an extraction context; treated like definitionExtract by the client-side Definition Extract (a name that does not exist in SDC 4.0; the retired itemExtractionContext is accepted the same way, presence only).Builder: add extension via import; Save ▾ → Definition Extract to run extractionImport a questionnaire with the extension on a group; extraction behaves as with definitionExtract.

sdc-questionnaire-sourceStructureMapCanonical reference to a FHIR StructureMap (Mapping Language) that transforms a resource fetched from the FHIR Base Server (e.g. Patient) into a QuestionnaireResponse to pre-fill answers. Executed entirely in the browser via the fhir-structuremap-js engine — only the resource fetch needs the server, no server-side $populate support required. Only a "#id" reference to a StructureMap added via the Contained Resources panel can be resolved (no server to fetch an external canonical URL).Properties → Source StructureMap field; Contained Resources panel to add the StructureMap; Answers ▾ → Fill via StructureMap to run itAdd a StructureMap resource via the Contained Resources panel, set Properties → Source StructureMap to "#" + its id, then Answers ▾ → Fill via StructureMap…, search for a patient, and click Run StructureMap. Answers are merged into the current form.
Questionnaire/$populateSends the current Questionnaire to a FHIR server's $populate operation to pre-fill answers from a patient record. Requires an SDC-capable server (FHIR Base Server, or SDC Server if set) configured in Settings.Answers ▾ → "↧ Fill from FHIR Server…" (enabled when a questionnaire is loaded)Open Answers ▾ → Fill from FHIR Server, search for a patient by name or type a Patient reference (e.g. Patient/123), then click "Fill from Server". Answers are merged into the current form.
Translation
Questionnaire translation (machine translation)Auto-translates all item labels, answer option displays, and UI strings into a target language using a machine-translation provider configurable in Settings → Translation API (Google Translate free, DeepL, LibreTranslate or OpenAI). Translations are stored in FHIR-standard _text.extension[translation] extensions. Items with rendering-xhtml preserve HTML formatting in the translated text. A language switcher in the header lets you preview the questionnaire in any translated language.Settings ▾ → "🌐 Translate questionnaire…"Open Settings ▾ → Translate questionnaire…, select a target language, click "Translate". Review and edit results in the table, then click "Apply translations". Switch the active language via the language button that appears in the header.
